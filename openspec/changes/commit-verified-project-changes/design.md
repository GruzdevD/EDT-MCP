# Design

## Context

`GitTool` использует настоящий Git CLI и общий механизм согласия; документация `docs/tools/git.md` прямо относит hooks, filters и конфигурацию машины к доверенной среде. Для подтверждения набора из снимка удобство CLI не нужно. Используем идентичность клиента, `entryId` и исходные версии из `inspect-project-snapshots`.

## Goals / Non-Goals

Одна операция фиксирует изменения одного репозитория на присоединённой разрешённой ветке. Нет транзакций между репозиториями, публикации, исполнения hooks, подписи внешней программой или обещания успешного тестирования выбранного подмножества.

## Decisions

1. Разделить `preview_project_commit(snapshotId, entryIds, message)` и `confirm_project_commit(planId)`. План связан с владельцем, областью, branch ref, parent SHA, итоговым tree ID, сообщением и сроком. Показывать переименование целиком (старый и новый путь); отказывать для конфликтного индекса, detached HEAD, частично staged выбранных файлов и преобразований, которые нельзя воспроизвести без внешней программы.
2. Через JGit построить дерево из родителя и выбранных версий снимка, включая удаления. Не создавать коммит из общего индекса и не вызывать Git CLI. На сервере отдельно проверять разрешение на запись, согласие на конкретный план и политику ветки; если обязательна внешняя подпись или hook, вернуть несовместимость, а не обходить политику.
3. Под блокировками репозитория/индекса повторить сверку и обновить ожидаемый ref через compare-and-swap. Новый индекс строить из актуального индекса с заменой только выбранных записей. Не писать в рабочее дерево. При отсутствии надёжной границы конкурентных правок не исполнять план. Журналировать ожидаемый ref, итоговый SHA и состояние операции до публикации: ref и индекс — разные файлы, общей атомарной операции для них нет.
4. После сбоя между обновлением ref и индекса сверять ожидаемые состояния. Завершать только доказуемо недоделанный шаг, не затирая более поздние правки. При неоднозначности блокировать повтор и сообщать `recovery_required` с известным SHA. Пока результат удерживается, повторное подтверждение возвращает ту же запись, а не строит новый commit object.

## Risks / Trade-offs

- Другой процесс меняет HEAD → привязать CAS к точному ref и родителю и координировать checkout; для неподдерживаемого совместного режима отказать.
- Человек успел изменить индекс во время восстановления → не откатывать чужую работу; показывать расхождение администратору.

## Migration Plan

Включать отдельным правом после поставки снимков. При отключении прекратить новые планы, завершить восстановление уже опубликованных коммитов. Откат плагина не перемещает Git-ветки назад.
