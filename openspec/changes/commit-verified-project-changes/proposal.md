# Proposal

## Why

Проверка diff не защищает от коммита другого содержимого: индекс на сервере может включать чужие файлы, а ветка или выбранный файл — измениться после ревью. Общий инструмент `git(command)` слишком широк для удалённого рабочего места.

## What Changes

- Предоставить предпросмотр коммита из явного набора `entryId` одного снимка и отдельное подтверждение ограниченного по времени плана. Сервер фиксирует сообщение, ветку, родителя и точное дерево до подтверждения.
- Фиксировать только показанный набор, оставлять чужие staged-изменения и рабочие файлы нетронутыми. Возвращать SHA и результат, доступный через MCP даже при потере первого ответа.
- Отдельное право записи. Без передачи Git-команд, флагов и путей с клиента. Push, создание MR и управление OpenSpec-документами не входят в сценарий коммита.

## Capabilities

### New Capabilities
- `verified-project-commits`: выборочная фиксация содержимого проверенного снимка в ветке проекта.

## Impact

Зависит от `inspect-project-snapshots`; может реализовываться независимо от `bind-yaxunit-to-snapshot`. Затронуты регистрация инструментов, политика записи, Git-слой плагина и тесты. `git(command)` остаётся необязательным и может быть выключен.
