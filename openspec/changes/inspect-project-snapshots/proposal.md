# Proposal

## Why

У агента нет клона 1С-проекта. Для ревью до коммита ему нужно повторно читать именно те изменения, которые были на машине EDT в момент снимка: одинаковый HEAD не означает одинаковое содержимое индекса и рабочего дерева.

## What Changes

- Снимать неизменяемое состояние разрешённого проекта, включая исходники расширений, явно включённых в область снимка. Возвращать `snapshotId`, ветку, HEAD, состав и признак согласованности модели с диском.
- Читать страницы манифеста и diff, сравнивать два снимка одной области. Достаточно EDT MCP; локальный Git, передача каталога и общий `git(command)` не требуются.
- Ограничить чтение типами исходников и проектами, заданными на сервере. Валидаторы UUID/BSL/СКД, YAxUnit, запись Git и изменение проектных документов не входят в этот срез.
- Выпустить и принять снимки на Windows EDT с рабочими деревьями на локальных дисках. Другие ОС и сетевые рабочие деревья не входят в этот срез.

## Capabilities

### New Capabilities
- `project-source-snapshots`: захват и чтение версионированного представления изменений проекта EDT.

### Modified Capabilities

## Impact

Новые инструменты плагина EDT MCP и их guides, серверное ограниченное хранилище снимков, тесты на временных Git-репозиториях. Контракт используют `bind-yaxunit-to-snapshot` и `commit-verified-project-changes`. Изменение харнесса поставляется отдельно.
