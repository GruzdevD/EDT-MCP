## Purpose

Позволяет ревьюеру без клона исследовать точную версию исходников и восстановить полный предмет проверки после нескольких build-коммитов одного change.

## ADDED Requirements

### Requirement: Разрешение истории проверки
Сервер SHALL вернуть для разрешённых repo, ветки и change наблюдаемый HEAD, design- и build-коммиты с родителями, итоговый build SHA и BASE — родителя самого раннего достижимого build-коммита change. Сервер SHALL различать диапазон BASE..final, отдельные build-дельты и проверку порядка фаз от наблюдаемого HEAD.

#### Scenario: Исправление после первого build
- **WHEN** между двумя build-коммитами change влиты сторонние изменения, а после итогового build появился design-коммит
- **THEN** клиент получает оба build SHA, полный итоговый diff от исходной базы, изменения каждого build с координатами для сверки сохранившихся участков и сведения о позднем design; сторонние изменения не помечаются как собственные только по попаданию в диапазон.

#### Scenario: База не установлена
- **WHEN** история недоступна, усечена лимитом или принадлежность первого build неоднозначна
- **THEN** ответ сообщает причину неполноты; родитель последнего коммита не выдаётся за BASE.

### Requirement: Адресное чтение и поиск в версии
Сервер SHALL предоставлять полные байты разрешённого файла и исчерпывающий поиск литерала в указанной области по фиксированной версии: сторона снимка HEAD/index/disk, дерево плана, удержанный эталон или достижимый commit. Каждая страница SHALL идентифицировать версию, охват, content ID и координаты; сервер MUST отличать отсутствие от неполного результата.

#### Scenario: Неизменённый метод вне diff
- **WHEN** проверяющий ищет тест или имя регистра в коммите, а живой модуль уже исправлен
- **THEN** все страницы поиска и чтение найденного метода относятся к коммиту, включая неизменённые файлы; изменения WT не меняют строки и ассерты.

#### Scenario: Патч недостаточен для pre-pass, UUID и СКД
- **WHEN** diff усечён, existing `.mdo` переименован, а для BSL и `.dcs` требуется полный контекст
- **THEN** доступны полные адресные версии, включая старый HEAD-blob, новый путь, соседнюю Configuration.mdo и разрешённые исключения на стороне результата, либо явный отказ с причиной. Конец списка записей не означает полноту тела файла.

### Requirement: Явный охват периметра и права чтения
Сервер SHALL позволять сверить до коммита рабочие изменения с HEAD и после коммита — пути и маркеры отдельных build-коммитов с итоговым деревом, включая разрешённые CI и test settings вне src. Если прав или данных недостаточно для требуемой области, сервер MUST сообщить неполноту без раскрытия закрытых путей. Каждый запрос и cursor MUST проверяться по текущим правам.

#### Scenario: Исправленный маркер и влитый CI
- **WHEN** первый build добавил отключение теста, второй убрал его, а CI-файл изменён только во влитой ветке
- **THEN** клиент может доказать по per-commit данным и финальным байтам, что ни одно из этих изменений не является сохранившейся правкой периметра данного change.

#### Scenario: Отозван доступ между страницами
- **WHEN** разрешение отозвано или обязательная часть репозитория вне read grant
- **THEN** продолжение не выдаёт закрытое содержимое; результат нельзя интерпретировать как полный поиск без попаданий.
