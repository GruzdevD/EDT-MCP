# Design

## Context

`GitRepositoryResolver` уже сопоставляет EDT-проект с репозиторием; корень репозитория может быть выше корня проекта. `compare_configurations` и `ComparisonSessionRegistry` управляют живыми сессиями сравнения модели. Ни такая сессия, ни SHA родителя не фиксируют версии файлов между страницами ответа.

## Goals / Non-Goals

Цель — единый серверный контракт для чтения, проверки актуальности и ограниченного удержания снимка потребителем. Захват не сохраняет редакторы, не вызывает resync и не создаёт refs в пользовательском Git. Первый срез не требует кэшировать репозиторий на клиенте.

## Decisions

1. `capture_project_snapshot(projectName, includedProjects[])` разрешает имена только через серверную политику. `inspect_project_snapshot(snapshotId, view, entryId?, compareTo?, cursor?)` принимает перечислимые виды `manifest`, `diff`; курсор связан со снимком и видом. В первом релизе доверенная идентичность привязана к выделенному однопользовательскому Windows EDT с защищённым входом и обязательной серверной аутентификацией. `Mcp-Session-Id` и аргументы запроса не удостоверяют личность. Без этой границы инструменты выключены.
2. Читать базу и индекс через JGit, дисковые версии — только для обычных файлов разрешённых типов под проверенными корнями исходников. Не следовать ссылкам, linked resources и подмодулям. Обход по рабочему дереву репозитория без учёта корней EDT-проектов неприемлем в монорепозитории. Не исполнять фильтры или программы репозитория. Если внешняя нормализация нужна для сравнения, помечать версию неподтверждённой.
   - Поддерживаются локальные диски Windows, без UNC и подключённых сетевых дисков. Открывать компоненты источника через Windows API (JNA) относительно уже проверенных дескрипторов каталогов, не следуя reparse points, включая symlink и junction. Свойства и байты проверять и читать через открытые дескрипторы, а не повторным открытием по строковому пути. Если локальность или безопасное открытие не подтверждены, отказать без чтения содержимого и без резервного чтения через Java NIO.
3. Хранить базовые, индексные и рабочие идентификаторы и материализованные байты изменённых файлов в закрытом ограниченном хранилище вне проекта. Для каждого проекта вычислять также отпечаток всех входов сборки, включая неизменившиеся; при неизвестном входе не обещать полноту. Сверять поколения модели, индекс, HEAD, состав и отпечатки через границу захвата; при конкурентной записи, которую нельзя исключить, не выдавать пригодный для записи/прогона снимок. Одних `mtime` и `git status` недостаточно.
4. Фиксировать порядок выдачи, статус модели `verified/diverged/unknown`, лимиты размера/времени и срок хранения. Неоднозначную пару rename показывать двумя записями. Внутренний потребитель может получить ограниченную lease на байты и манифест; по окончании срока не перечитывать живое дерево под прежним ID.

## Risks / Trade-offs

- Большая конфигурация → квоты по клиенту, общий предел, дедупликация, пагинация; невозможность полного захвата отличима от пустого результата.
- EDT не подтверждает конкретную сериализацию → разрешить просмотр стабильных байтов с `unknown`, заблокировать зависимые подтверждения.
- Истечение срока во время чтения → удерживать активную страницу до конца вызова; между вызовами выдавать явный отказ.

## Migration Plan

Включать чтение отдельно на разрешённом сервере. При отключении прекратить новый доступ, освободить leases и удалить временные данные по политике хранения; миграции проекта нет.
