# Spec Delta

## Purpose

Позволяет удалённому клиенту зафиксировать показанные на ревью изменения в одной серверной ветке, не захватывая чужую работу из общего индекса.

## ADDED Requirements

### Requirement: Предпросмотр выбранного набора
Сервер SHALL принимать ID стабильного дискового снимка со статусом `verified` или `unknown`, непустой явный набор `entryId` одного репозитория и текст сообщения. Предпросмотр SHALL содержать `modelStatus`, ветку, родительский SHA, сообщение, список версий и идентификатор подтверждения со сроком действия. Предпросмотр MUST NOT менять индекс, ветку или рабочие файлы.

#### Scenario: В индексе есть посторонний файл
- **WHEN** клиент выбрал только изменённый модуль, а в индексе есть отдельное staged-изменение
- **THEN** план показывает лишь версию модуля из рабочего дерева снимка и не включает чужое изменение.

#### Scenario: Стабильный снимок без подтверждения модели
- **WHEN** стабильный дисковый снимок имеет статус `unknown` и остальные условия допуска соблюдены
- **THEN** сервер выдаёт план выбранных дисковых версий и показывает `modelStatus: unknown`.

#### Scenario: Зафиксировано расхождение модели
- **WHEN** клиент предъявляет снимок со статусом `diverged`
- **THEN** сервер отказывает без выдачи плана.

### Requirement: Фиксация ровно показанного состояния
Только при действующем праве записи и подтверждении плана сервер SHALL создать один коммит поверх ожидаемого HEAD. При смене ветки, HEAD, выбранного существующего файла или его индексной версии, а также при расхождении модели сервер MUST отказать. Частично staged версии не допускаются. Под блокировками Git сервер MUST проверить отсутствие удалённых файлов и старых путей переименований непосредственно перед обновлением ветки. Позднее создание файла SHALL остаться новой незакоммиченной правкой.

#### Scenario: Успешный выборочный коммит
- **WHEN** после просмотра разрешённый пользователь подтвердил неизменившийся план
- **THEN** родитель и diff результата совпадают с планом, возвращён полный SHA, выбранные файлы чисты относительно нового HEAD, остальные staged и unstaged правки сохранены.

#### Scenario: Устаревший план
- **WHEN** выбранный новый модуль заменён между предпросмотром и подтверждением либо HEAD сдвинут параллельным коммитом
- **THEN** операция требует нового снимка и не фиксирует ни старый, ни новый вариант автоматически.

#### Scenario: Удалённый файл восстановлен до финальной проверки
- **WHEN** выбранный удалённый файл или старый путь переименования существует в момент проверки перед обновлением ветки
- **THEN** сервер отклоняет план без изменения ветки и индекса.

#### Scenario: Удалённый файл восстановлен после финальной проверки
- **WHEN** выбранный удалённый файл или старый путь переименования появляется после финальной проверки отсутствия
- **THEN** коммит фиксирует просмотренное удаление, а появившийся файл остаётся в рабочем дереве как новая незакоммиченная правка.

### Requirement: Ограниченное и повторяемое подтверждение
Сервер MUST привязывать план и его результат к разрешённому клиенту и репозиторию, проверять полномочия при каждом вызове и исключать повторную запись по одному подтверждению. Подтверждение SHALL работать без общего `git(command)` и не давать права публикации.

#### Scenario: Потерян ответ сервера
- **WHEN** после записи ветки клиент повторил запрос с тем же идентификатором в пределах срока хранения результата
- **THEN** сервер возвращает ранее созданный SHA либо статус восстановления той же операции; второй коммит не создаётся.

#### Scenario: Право отозвано
- **WHEN** клиент получил предпросмотр, но до подтверждения утратил право на запись
- **THEN** сервер отказывает независимо от наличия идентификатора плана.
